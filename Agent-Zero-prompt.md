# Zero prompt for repo setup

## Existing Repo

Read `AGENTS_TEMPLATE.md` and follow its four-phase working agreement. In Phase 1, inspect the repository without editing tracked files. Initialize the `.agent/` working files as directed by Phase 1. Use relevant maintained docs and prior closeouts to construct the task brief, following the selective reading policy. Plan a repo-specific root `AGENTS.md`, mapping documentation ownership to existing files or sections with clear scope boundaries; then stop for approval. In Phase 2, create the draft by replacing the placeholders before `## Working agreement`, pruning inapplicable repo-specific content and optional documentation roles, and preserving the policy sections from `## Working agreement` onward, including documentation maintenance, unless the user explicitly changes them. Propose new documents only for distinct needs that existing owners cannot serve. In Phase 3, incorporate review feedback and use the debugging loop for problems found during review. After the user approves the draft, remove `AGENTS_TEMPLATE.md`, leave the finalized `AGENTS.md` at the repository root, and complete Phase 4 reconciliation and closeout.

## New Repo with design specification

Read `AGENTS_TEMPLATE.md` and `MY_DESIGN.md`, then follow the template's four-phase working agreement. In Phase 1, inspect the design and any existing repository files without editing tracked files. Initialize the `.agent/` working files as directed by Phase 1. Use relevant maintained docs and any prior closeouts to construct the task brief, following the selective reading policy. Plan a repo-specific root `AGENTS.md`, mapping applicable documentation roles to existing files or sections and identifying any distinct unmet needs; then stop for approval. In Phase 2, create the draft by replacing the placeholders before `## Working agreement`, pruning inapplicable repo-specific content and optional documentation roles, and preserving the policy sections from `## Working agreement` onward, including documentation maintenance, unless the user explicitly changes them. Define clear ownership boundaries without creating a full documentation suite by default. Base the guidance on the design, but do not present unimplemented files or commands as existing functionality. In Phase 3, incorporate review feedback and use the debugging loop for problems found during review. After the user approves the draft, remove `AGENTS_TEMPLATE.md`, leave the finalized `AGENTS.md` at the repository root, and complete Phase 4 reconciliation and closeout.
